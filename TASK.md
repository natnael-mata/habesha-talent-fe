## Phase 4 — Finish review

An independent reviewer audited the build against the direction contract and the
chosen world's craft reference. Applied:

- [x] **T25** **Faces were invisible on 40% of prints.** The `afro` and `locs`
      hair masses reached below the eye line, painting black marks on black
      hair — every such card was a blob with a floating lip, including all ten
      tiles on the player. Both clamped above `CY - 0.30ry`.
- [x] **T26** **The lettering is now screened.** Display type carries the
      halftone dot structure the reference world is built on, via a
      `background-clip: text` pseudo-element over the black plate, and the
      misregistration offsets nearly doubled. This was the largest gap to the
      craft bar.
- [x] **T27** **Error state moved off pink.** It shared a field with the primary
      button and the two read as one object. Now marigold with a black key
      plate, and recorded in DESIGN.md's ink-state table.
- [x] **T28** **The foil is crumpled, not brushed.** Fractal-noise luminance at
      620px plus two faint creases under the fine striations, which alone read
      as linen.
- [x] **T29** **The squeegee is visible and keyboard-operable.** It was
      `opacity: 0` until a drag began — the one control the contract names could
      not be found. Now a grip at rest, `role="slider"`, arrow-key stepping.
- [x] **T30** **The contract's 104px promise restored** on the login headline;
      the fold was bought back from padding instead of from the type.
- [x] **T31** **The view count reads as an edition size** on the player, in the
      margin at figure scale, instead of the third cell of a fact table.
- [x] **T32** **Ethio Telecom endorsement now on every page.** It appeared only
      on the two logged-out screens; Feed, Watch and Upload had no footer at all.
- [x] **T33** **Dropzone and empty state rebuilt as un-inked frames** — the
      dashed rectangle was the last stock component in the build.
- [x] **T34** Dead `wide` prop removed from `PerformerPrint`; mobile rack
      squared so the login form is reachable on a 390×844 screen.

Not applied: the reviewer also asked for hand-drawn margin marks (signature,
tick, arrow) and dashed annotation rules to raise ornament density further. Left
undone deliberately — it is the one item that adds decoration rather than
fixing something, and it is better judged against real content.

## Phase 5 — Registration is external (corrected 2026-08-13)

Bereket confirmed the real mechanism: **subscription happens by SMS, Ethio
Telecom's VAS provisions the subscriber and issues a password, and the VAS
`POST`s phone number + password to us.** The app never creates accounts.

- [x] **T35** PRODUCT.md rewritten around the external provisioning flow.
- [x] **T36** The signup form is **gone**. `/register` now redirects to
      `/subscribe`, which is an instructions page: what to SMS, where, what
      arrives back, then log in. The SMS keyword and shortcode are set at poster
      scale because the action happens in another app entirely.
- [x] **T37** `register()` removed from `AuthContext` — the UI has no way to
      mint an account even by mistake.
- [x] **T38** `provisionSubscriber()` in `src/api/mock.ts` documents the inbound
      contract: authenticated, idempotent on `phone_number`, bcrypt on receipt.
- [x] **T39** **The real endpoint is built** — `habesha-talent-be`, Node/Express port of
      the `register.php` sample, with MySQL schema and unit tests. See
      [the habesha-talent-be repo README](the habesha-talent-be repo README).
- [x] **T40** SMS keyword and shortcode live in `src/config.ts` behind a
      `confirmed: false` flag; while it is false, the page shows them as
      unconfirmed. Flip it once ET signs them off and the warning disappears.

## Flagged — needs Bereket

- [ ] **F0 — The deployment host for the VAS callback URL.** Ethio Telecom needs
      a final `https://<host>/api/vas/register` to configure on their platform.
      It needs a real domain with a publicly valid TLS certificate — the request
      carries a plaintext password, and SDP platforms commonly reject
      self-signed certs and do not follow redirects. **Blocked on: which
      domain.**
- [ ] **F0b — Two values only ET can give:** the SMS keyword and shortcode
      (placeholders `TALENT` / `8XXX` in `src/config.ts`), and the source IPs
      their SDP calls from, for `VAS_IP_ALLOWLIST`.
- [ ] **F0c — The database-backed path is untested locally.** MariaDB is running
      on this machine but root needs a password I do not have, so `schema.sql`
      was never applied and the insert/idempotency path has not been exercised.
      Auth, validation, normalisation and the 405/401/400/422 responses are all
      verified; the SQL is not. `the habesha-talent-be repo README` § Test it has the exact
      commands.
- [ ] **F1 — Amharic wording review.** Every string in `locales/am.json` is
      authored, not translated by a native speaker. Grammar and register need a
      pass, especially: `promo_body`, `upload_data_note`, `err_rate_limited`,
      `empty_body`, and the three `promo_step_*_b` lines.
- [ ] **F2 — Logo.** The wordmark and app mark are authored placeholders

- [ ] **F3 — Ethio Telecom endorsement wording.** The footer currently reads
